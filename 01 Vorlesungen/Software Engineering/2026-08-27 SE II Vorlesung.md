# Software engineering
**Definition**: Entwickeln von brauchbarer Software, die den Anforderungen genügt

**Entwickeln**: 
- Was ist zu tun?
- Welche Werkzeuge?
- Was ist das Vorgehen?

**brauchbare Software**:
- Was sind die Kriterien
- Wie gebaut

**Anforderungen**:
- Woher bekommt man sie?
- Sicherstellen dass man sie versteht
- Wie prüft man das?

## Brainstorming - was müssen wir tun
- Anforderungen der Zielgruppen 
	- Gesetzliche Vorgaben
- Ressourcen (Teamgröße, Zeit, Budget)
- Art der Software
- Design (Erweiterbarkeit, Flexibilität)
- Sprache/Technologie (Tools)
- Architektur
- Fachliches Konzept
- Infrastruktur
- UX
- Schulung der Nutzer
- Testen
- Implementation (Code schreiben)

## Modell für Softwareengineering
Modell ist kein Vorgehensmodell => Modell ist ein Beziehungsmodell
- **Spezifikation** => Was ist eigentlich gefordert
- Spezifikation geht immer mehr ins Detail
- **Integration** => Ich baue die software
- Integration endet mit der Kundenadoption
- Im Graph: **Detaillierung** => Abstraktion der Software
- **Konfigurationsmanagement**: Alles was ich brauche, um zu entwickeln
- **Validierung**: Spezifizierungsast muss absteigend auf Lücken geprüft werden
- **Verfikation**: Integrationsast => Baue ich nach Vorgaben?

## Einflussfaktoren
Dinge die Software-Entwicklung beeinflussen:
- Kommunikationsstruktur im Software-Team spiegelt sich in der Software wieder
- Menschliche Sprache ist ungenau => Übersetzung in die Maschine
